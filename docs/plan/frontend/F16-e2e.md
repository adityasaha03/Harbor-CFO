# F16 End-to-end tests (Playwright)

Depends: F11, F12, B17. Priority: P0. Read first: PRODUCT_BRIEF.md; B17 spec.

## Goal

Two automated journeys that double as demo evidence: the Owner's closed loop and the Employee's denial.

## Files

- `apps/web/playwright.config.ts`, `apps/web/e2e/global-setup.ts` (runs `seed:auth` and `seed:demo`, starts web and api, agent in replay mode), `apps/web/e2e/helpers/auth.ts`
- `apps/web/e2e/owner-journey.spec.ts`, `apps/web/e2e/employee-denial.spec.ts`, `apps/web/e2e/isolation.spec.ts`

## Specification

- **Owner journey**: sign in as `owner@harbor.demo` -> dashboard shows the cash dip and the floor-breach alert -> forecast drill-down for 2026-11-07 -> financing page lists the bridge offer with total cost 3,000.00 and the excluded slow loan -> scenario studio comparison shows 38,800.00 for the bridge -> create proposal -> approve and execute with the Owner -> success view with operation id -> forecast day-21 value is now 38,800.00 -> the Proof page audit log shows `financing.approve` and `financing.execute`.
- **Employee denial**: sign in as `employee@harbor.demo` -> the approve/execute buttons are disabled -> using the page's request context, call the execute endpoint directly with the Employee's token and expect 403 -> ledger entry count unchanged (verify through the API).
- **Isolation**: sign in as `owner@pearl.demo`; requesting Harbor's proposal id returns 404 and no Harbor data appears in any page.
- Record traces and a video of the Owner journey on success (useful for the submission video). Tests are deterministic: reset the demo with `reset:demo` in `beforeAll`.
